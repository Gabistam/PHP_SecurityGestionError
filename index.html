🔒 Qu'est-ce que la sécurité web ?

La sécurité web consiste à protéger votre application contre les attaques malveillantes

  • Protéger les données : Informations personnelles, mots de passe, données bancaires
  • Préserver l'intégrité : Empêcher la modification non autorisée du contenu
  • Assurer la disponibilité : Éviter que l'application soit rendue inutilisable
  • Maintenir la confidentialité : Contrôler qui accède à quoi

⚠️ Les risques sans sécurité

  • Vol de données : Piratage de comptes utilisateurs, fuite d'informations
  • Défacement : Modification du contenu de votre site
  • Injection de malware : Infection des visiteurs de votre site
  • Réputation ternie : Perte de confiance des utilisateurs
  • Sanctions légales : Amendes RGPD, poursuites judiciaires
🎯 Analogie : La sécurité web, c'est comme la sécurité de votre maison : vous fermez à clé, vous vérifiez qui sonne avant d'ouvrir, et vous ne laissez pas traîner vos objets de valeur !

📊 Statistiques choc

  • 43% des cyberattaques visent les petites entreprises
  • Une attaque toutes les 39 secondes sur le web
  • 90% des violations de données sont évitables avec de bonnes pratiques
  • PHP représente 77% des sites web - c'est une cible privilégiée !
⚠️
Réalité du terrain : Un site non sécurisé peut être compromis en quelques minutes. Les robots malveillants scannent internet 24h/24 à la recherche de failles à exploiter !

⚡ Gestion des erreurs et exceptions en PHP

💡 Maîtriser le système d'exceptions PHP ▼

🎯 Objectif : Apprendre à gérer proprement les erreurs avec try-catch et créer des exceptions personnalisées pour sécuriser vos applications.

⚡ Pourquoi bien gérer les erreurs ?

Une mauvaise gestion des erreurs peut révéler des informations sensibles :

  • Chemins de fichiers : Structure de votre serveur
  • Noms de base de données : Architecture technique
  • Requêtes SQL : Structure des tables
  • Versions logicielles : Vulnérabilités connues exploitables
🎯 Principe de base : Pour l'utilisateur : message simple et rassurant. Pour le développeur : log détaillé avec toutes les informations techniques.

🔧 Le système try-catch en PHP

⚡ Try-Catch Basique

Structure : Capture et traite les exceptions

// Bloc try : code susceptible de générer une erreur
try {
    // Appel d'une fonction qui pourrait échouer
    $result = riskyFunction();

} catch (Exception $e) {
    // Bloc catch : on capture l'exception si elle survient

    // On enregistre l'erreur technique dans les logs (pour nous, développeurs)
    logError($e->getMessage());

    // On affiche un message simple à l'utilisateur (pas de détails techniques !)
    showUserError("Une erreur est survenue. Veuillez réessayer.");
}

🔒 Exceptions Personnalisées

Avantage : Gestion spécifique par type d'erreur

// 1. CRÉATION D'EXCEPTIONS PERSONNALISÉES
// On crée des classes d'exception spécifiques pour chaque type d'erreur

// Exception pour les erreurs de base de données
class DatabaseException extends Exception {}

// Exception pour les erreurs de validation de données
class ValidationException extends Exception {}

// 2. UTILISATION AVEC GESTION DIFFÉRENCIÉE
try {
    // On tente de valider les données utilisateur
    validateUser($data);

} catch (ValidationException $e) {
    // Si c'est une erreur de validation (email invalide, champ manquant, etc.)
    echo "Vos données sont incorrectes : " . $e->getMessage();

} catch (DatabaseException $e) {
    // Si c'est une erreur de base de données (connexion perdue, table inexistante, etc.)
    logError("DB Error: " . $e->getMessage());
    echo "Service temporairement indisponible.";
}

🛡️ Logging Sécurisé

Principe : Enregistrer sans exposer

/**
 * Fonction de logging sécurisé
 * Enregistre les erreurs dans un fichier LOG sans les afficher à l'utilisateur
 */
function logError($message) {
    // 1. Création d'une entrée de log avec horodatage
    $logEntry = date('Y-m-d H:i:s') . " - " . $message . PHP_EOL;

    // 2. Enregistrement dans un fichier sécurisé (HORS du dossier web public)
    // FILE_APPEND : ajoute à la fin du fichier sans écraser le contenu existant
    file_put_contents(
        '/secure/logs/error.log',  // Chemin sécurisé (pas dans public_html/)
        $logEntry,
        FILE_APPEND
    );

    // Astuce : En production, utilisez aussi error_log() de PHP
    // error_log($message, 3, '/secure/logs/error.log');
}

⚠️ Gestion PDO

Spécial : Erreurs de base de données

// CONNEXION SÉCURISÉE À LA BASE DE DONNÉES AVEC PDO
try {
    // Création de la connexion PDO (PHP Data Objects)
    $pdo = new PDO($dsn, $user, $pass);

    // IMPORTANT : Configuration du mode d'erreur en EXCEPTION
    // Par défaut, PDO masque les erreurs (mode silencieux) - DANGEREUX !
    // On force PDO à lancer des exceptions pour capturer les erreurs
    $pdo->setAttribute(
        PDO::ATTR_ERRMODE,          // Attribut : mode de gestion d'erreurs
        PDO::ERRMODE_EXCEPTION      // Valeur : lancer des exceptions
    );

} catch (PDOException $e) {
    // Capture spécifique des erreurs PDO (hérite de Exception)

    // On log l'erreur technique complète pour le debug
    logError("DB Error: " . $e->getMessage());

    // On affiche un message générique à l'utilisateur (JAMAIS les détails !)
    die("Service temporairement indisponible. Veuillez réessayer plus tard.");
}

📊 Le Top 3 OWASP

L'OWASP Top 10 liste les vulnérabilités web les plus critiques. Voici le trio de tête :

  • Injection SQL : Manipulation des requêtes de base de données

💉 Injection SQL : La reine des vulnérabilités

❌ Code Vulnérable - Concaténation directe

▼

⚠️ DANGEREUX : Ne jamais concaténer directement les données utilisateur dans les requêtes SQL !

// ⚠️ CODE VULNÉRABLE - NE JAMAIS FAIRE CELA !

// On récupère directement les données du formulaire
$username = $_POST['username'];
$password = $_POST['password'];

// ❌ FAILLE DE SÉCURITÉ : Concaténation directe dans la requête SQL
// Les variables sont insérées DIRECTEMENT dans la chaîne SQL
$sql = "SELECT * FROM users WHERE
    username = '$username' AND
    password = '$password'";

// Exécution de la requête vulnérable
$result = mysqli_query($conn, $sql);

// 🚨 PROBLÈME : Un attaquant peut injecter du code SQL malveillant
// Exemple : username = "admin' OR '1'='1' --"
// La requête devient : SELECT * FROM users WHERE username = 'admin' OR '1'='1' --' AND password = '...'
// Résultat : Connexion réussie SANS mot de passe !

🎯 Exemple d'attaque : admin' OR '1'='1' --

✅ Code Sécurisé - Requêtes préparées (PDO)

▼

🛡️ BONNE PRATIQUE : Utilisez TOUJOURS les requêtes préparées avec PDO

// ✅ CODE SÉCURISÉ - BONNE PRATIQUE

// 1. Récupération des données utilisateur (toujours non fiables !)
$username = $_POST['username'];
$password = $_POST['password'];

// 2. Création de la requête avec des PLACEHOLDERS (?)
// Les ? sont des emplacements pour les valeurs, SÉPARÉS du code SQL
$sql = "SELECT * FROM users WHERE
    username = ? AND password = ?";

// 3. PRÉPARATION de la requête (compilation SQL)
// La structure SQL est figée, impossible de la modifier ensuite
$stmt = $pdo->prepare($sql);

// 4. EXÉCUTION avec liaison des paramètres
// PDO échappe automatiquement les valeurs dangereuses
// Les données sont transmises SÉPARÉMENT de la requête SQL
$stmt->execute([$username, $password]);

// 🛡️ PROTECTION : Même si $username = "admin' OR '1'='1' --"
// PDO traite cette chaîne comme UNE VALEUR LITTÉRALE, pas comme du code SQL
// L'injection est impossible !

🔒 Avantage : Séparation totale entre code SQL et données

🎭 XSS : Injection de JavaScript malveillant

❌ Code Vulnérable - Affichage direct sans échappement

▼

⚠️ DANGEREUX : Ne jamais afficher directement les données utilisateur sans échappement HTML !

// ⚠️ CODE VULNÉRABLE - FAILLE XSS !

// Affichage DIRECT des données utilisateur sans filtrage
echo "Bonjour " . $_GET['nom'];

// 🚨 DANGER : Si nom = ""
// Le navigateur EXÉCUTE le JavaScript malveillant !
// Conséquences : vol de cookies, redirection, keylogger...

🎯 Attaque possible : ?nom=<script>alert('XSS!')</script>

✅ Code Sécurisé - htmlspecialchars() pour échapper

▼

🛡️ BONNE PRATIQUE : Utilisez TOUJOURS htmlspecialchars() avant d'afficher des données utilisateur

// ✅ CODE SÉCURISÉ - Protection XSS

// htmlspecialchars() convertit les caractères spéciaux HTML
// en entités HTML (< > & etc.)
echo "Bonjour " . htmlspecialchars(
    $_GET['nom'],        // Donnée à échapper
    ENT_QUOTES,          // Échapper aussi les guillemets simples et doubles
    'UTF-8'              // Encodage (important pour les accents !)
);

// 🛡️ PROTECTION :
// Input : 
// Output affiché : <script>alert('XSS!')</script>
// Le navigateur affiche le texte, mais N'EXÉCUTE PAS le code !

🔒 Résultat : <script> devient &lt;script&gt; (texte affiché, pas exécuté)

✅ Validation et filtrage des données

💡 Ne jamais faire confiance aux données utilisateur ▼

🎯 Objectif : Apprendre à valider, filtrer et échapper toutes les données provenant des utilisateurs pour sécuriser votre application.

🔍 Principe fondamental

Rule #1 : Ne JAMAIS faire confiance aux données utilisateur !

  • Tout provenant de $_GET, $_POST, $_COOKIE est suspect
  • Les données d'URL peuvent être modifiées
  • Les formulaires HTML peuvent être contournés
  • JavaScript côté client peut être désactivé/modifié
🎯 Analogie : Traiter les données utilisateur comme un courrier suspect : on l'examine sous toutes les coutures avant de l'ouvrir !

🔍 Les étapes de la validation

1️⃣ Vérifier

Présence des données obligatoires

2️⃣ Valider

Format et type corrects

3️⃣ Filtrer

Nettoyer les données

4️⃣ Échapper

Avant affichage/stockage

🛠️ Outils de validation PHP

🛡️ filter_var()

Usage : Validation et filtrage intégrés de PHP

// ═══════════════════════════════════════════════════════════
// FONCTION filter_var() : Validation native de PHP
// ═══════════════════════════════════════════════════════════

// ────────────────────────────────────────────────────────
// VALIDATION D'EMAIL
// ────────────────────────────────────────────────────────
$email = filter_var(
    $_POST['email'],         // Valeur à valider
    FILTER_VALIDATE_EMAIL    // Filtre : format email RFC 5321
);

// Résultat :
// - Si valide : retourne l'email
// - Si invalide : retourne false
if ($email === false) {
    echo "Email invalide !";
}

// ────────────────────────────────────────────────────────
// VALIDATION D'ENTIER AVEC OPTIONS
// ────────────────────────────────────────────────────────
$age = filter_var(
    $_POST['age'],
    FILTER_VALIDATE_INT,     // Filtre : nombre entier
    array("options" => array(
        "min_range" => 1,    // Minimum : 1
        "max_range" => 120   // Maximum : 120
    ))
);

// Validation stricte : doit être un entier entre 1 et 120
if ($age === false) {
    echo "Âge invalide ! Doit être entre 1 et 120 ans.";
}

// 💡 AUTRES FILTRES UTILES :
// - FILTER_VALIDATE_URL : valide une URL
// - FILTER_VALIDATE_IP : valide une adresse IP
// - FILTER_VALIDATE_BOOLEAN : valide un booléen
// - FILTER_SANITIZE_STRING : nettoie une chaîne (supprime balises HTML)

⚡ Expressions régulières (REGEX)

Usage : Validation de formats complexes personnalisés

// ═══════════════════════════════════════════════════════════
// EXPRESSIONS RÉGULIÈRES (REGEX) : Pour formats personnalisés
// ═══════════════════════════════════════════════════════════

// ────────────────────────────────────────────────────────
// VALIDATION NUMÉRO DE TÉLÉPHONE FRANÇAIS (10 chiffres)
// ────────────────────────────────────────────────────────
$pattern = '/^[0-9]{10}$/';
// Décomposition du pattern :
// ^ : début de la chaîne
// [0-9] : un chiffre de 0 à 9
// {10} : exactement 10 fois
// $ : fin de la chaîne

if (preg_match($pattern, $phone)) {
    echo "Numéro de téléphone valide !";
} else {
    echo "Format invalide. Exemple : 0612345678";
}

// ────────────────────────────────────────────────────────
// VALIDATION NOM D'UTILISATEUR
// ────────────────────────────────────────────────────────
$pattern = '/^[a-zA-Z0-9_]{3,20}$/';
// Décomposition :
// [a-zA-Z0-9_] : lettres, chiffres et underscore uniquement
// {3,20} : longueur entre 3 et 20 caractères
// Interdit : espaces, caractères spéciaux, emojis

if (preg_match($pattern, $username)) {
    echo "Nom d'utilisateur valide !";
} else {
    echo "Nom invalide. 3-20 caractères alphanumériques uniquement.";
}

// 💡 AUTRES PATTERNS UTILES :
// Code postal FR : '/^[0-9]{5}$/'
// Mot de passe fort : '/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/'
// Plaque immatriculation : '/^[A-Z]{2}-[0-9]{3}-[A-Z]{2}$/'

🔒 Fonctions d'échappement

Usage : Préparer les données pour affichage ou stockage sécurisé

// ═══════════════════════════════════════════════════════════
// FONCTIONS D'ÉCHAPPEMENT SELON LE CONTEXTE
// ═══════════════════════════════════════════════════════════

// 1️⃣ Pour l'affichage HTML (protection XSS)
// Convertit les caractères spéciaux HTML en entités
$safeHtml = htmlspecialchars(
    $data,           // Donnée à échapper
    ENT_QUOTES,      // Échapper guillemets simples et doubles
    'UTF-8'          // Encodage caractères
);
echo $safeHtml;

// 2️⃣ Pour les URLs (paramètres GET)
// Encode les caractères spéciaux pour URL
$safeUrl = urlencode($data);
echo "page.php?name=" . $safeUrl;

// 3️⃣ Pour JavaScript (transmission de données PHP → JS)
// Convertit en JSON sécurisé
$safeJson = json_encode($data);
echo "";

// 4️⃣ Pour les attributs HTML
// Échappement spécifique pour les attributs
$safeAttr = htmlspecialchars($data, ENT_QUOTES);
echo '';

// 💡 RÈGLE D'OR : Toujours échapper selon le contexte de sortie !

⚡ Configuration PHP

Serveur : Durcir la configuration php.ini en production

# Dans php.ini en production

# Désactiver l'affichage des erreurs aux utilisateurs
display_errors = Off

# Activer le logging des erreurs dans un fichier
log_errors = On

# Masquer la version PHP dans les headers HTTP
expose_php = Off

# Désactiver l'ouverture de fichiers distants
allow_url_fopen = Off
allow_url_include = Off

# Sécuriser les cookies de session
session.cookie_httponly = 1
session.cookie_secure = 1

# Limiter la durée de vie des sessions (30 minutes)
session.gc_maxlifetime = 1800

# Limiter la taille des uploads
upload_max_filesize = 5M
post_max_size = 8M

⚠️ Permissions fichiers

Système : Appliquer les droits d'accès minimaux (principe du moindre privilège)

# Permissions recommandées sur serveur Linux

# Fichiers PHP : 644 (lecture pour tous, écriture propriétaire uniquement)
chmod 644 *.php

# Dossiers : 755 (exécution nécessaire pour naviguer)
chmod 755 /var/www/

# Fichiers de configuration sensibles : 600 (propriétaire uniquement)
chmod 600 config.php
chmod 600 .env

# Dossier d'uploads : 755 (PAS 777 qui serait dangereux !)
chmod 755 uploads/

# Logs : 640 (lecture groupe web, écriture propriétaire)
chmod 640 /var/log/app.log

# ⚠️ JAMAIS : chmod 777 (accès total = danger !)

🎯 Points clés à retenir

⚡ Gestion d'erreurs - Récapitulatif

Les erreurs bien gérées protègent votre application et préservent l'expérience utilisateur.


// ═══════════════════════════════════════════════════════════
// CONFIGURATION PRODUCTION (php.ini)
// ═══════════════════════════════════════════════════════════

// ✅ NE JAMAIS afficher les erreurs aux utilisateurs
display_errors = Off

// ✅ TOUJOURS logger les erreurs pour le debug
log_errors = On
error_log = /var/log/php_errors.log

// ═══════════════════════════════════════════════════════════
// STRUCTURE DE GESTION
// ═══════════════════════════════════════════════════════════

try {
    // 1️⃣ Code potentiellement risqué
    $result = executeOperation();

} catch (SpecificException $e) {
    // 2️⃣ Logger les détails techniques (fichiers seulement)
    error_log("Erreur technique: " . $e->getMessage());

    // 3️⃣ Message simple pour l'utilisateur
    echo "Une erreur est survenue. Veuillez réessayer.";
}

// 💡 RÈGLE D'OR : Séparer complètement les messages techniques et utilisateur !

Points essentiels :

  • ✅ Try-catch systématique sur les opérations critiques
  • ✅ Logging sécurisé (jamais de données sensibles)
  • ✅ Messages utilisateur génériques et simples
  • ✅ Exceptions personnalisées pour typer les erreurs

⚠️ Top 3 vulnérabilités - Protection essentielle

Ces trois failles représentent la majorité des attaques web. Maîtrisez-les absolument !


// ═══════════════════════════════════════════════════════════
// 1️⃣ INJECTION SQL - TOUJOURS utiliser les requêtes préparées
// ═══════════════════════════════════════════════════════════

// ❌ JAMAIS CELA :
$sql = "SELECT * FROM users WHERE id = " . $_GET['id'];

// ✅ TOUJOURS CELA :
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->execute([':id' => $_GET['id']]);

// ═══════════════════════════════════════════════════════════
// 2️⃣ XSS (Cross-Site Scripting) - TOUJOURS échapper
// ═══════════════════════════════════════════════════════════

// ❌ JAMAIS CELA :
echo "
" . $_POST['nom'] . "
";

// ✅ TOUJOURS CELA :
echo "
" . htmlspecialchars($_POST['nom'], ENT_QUOTES, 'UTF-8') . "
";

// ═══════════════════════════════════════════════════════════
// 3️⃣ CSRF (Cross-Site Request Forgery) - TOUJOURS vérifier token
// ═══════════════════════════════════════════════════════════

// ✅ Dans le formulaire :
if (empty($_SESSION['csrf_token'])) {
    $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
}
// 

// ✅ À la soumission :
if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) {
    die('Token CSRF invalide');
}

Mémo anti-vulnérabilités :

  • 🚨 SQL : Requêtes préparées uniquement (PDO ou MySQLi)
  • 🚨 XSS : htmlspecialchars() sur TOUTES les sorties
  • 🚨 CSRF : Token aléatoire dans chaque formulaire

🛡️ Validation données - Ne faites confiance à personne

Toutes les entrées utilisateur doivent être validées côté serveur, sans exception.


// ═══════════════════════════════════════════════════════════
// PRINCIPE FONDAMENTAL : VALIDATION SERVEUR OBLIGATOIRE
// ═══════════════════════════════════════════════════════════

// 💡 La validation JavaScript côté client peut être désactivée !
// 🛡️ TOUJOURS valider sur le serveur, même si validation côté client

// ═══════════════════════════════════════════════════════════
// EXEMPLES DE VALIDATION
// ═══════════════════════════════════════════════════════════

// 1️⃣ Validation d'email
$email = filter_var($_POST['email'], FILTER_VALIDATE_EMAIL);
if (!$email) {
    throw new Exception("Email invalide");
}

// 2️⃣ Validation d'entier avec limites
$age = filter_var($_POST['age'], FILTER_VALIDATE_INT, [
    'options' => ['min_range' => 18, 'max_range' => 120]
]);

// 3️⃣ Validation format avec regex
if (!preg_match('/^[a-zA-Z0-9_]{3,20}$/', $_POST['username'])) {
    throw new Exception("Nom d'utilisateur invalide");
}

// 4️⃣ Whitelist : autoriser uniquement certaines valeurs
$allowedColors = ['rouge', 'bleu', 'vert'];
if (!in_array($_POST['color'], $allowedColors, true)) {
    throw new Exception("Couleur non autorisée");
}

// ═══════════════════════════════════════════════════════════
// ÉCHAPPEMENT SELON LE CONTEXTE
// ═══════════════════════════════════════════════════════════

// Pour HTML :
htmlspecialchars($data, ENT_QUOTES, 'UTF-8');

// Pour URL :
urlencode($data);

// Pour JavaScript :
json_encode($data, JSON_HEX_TAG | JSON_HEX_AMP);

Checklist validation :

  • ✅ Valider TOUJOURS côté serveur (jamais seulement client)
  • ✅ Utiliser filter_var() pour types standards
  • ✅ Préférer whitelist (autoriser) plutôt que blacklist (interdire)
  • ✅ Échapper selon le contexte (HTML ≠ URL ≠ JavaScript)

🔒 Authentification - Sécuriser l'accès utilisateur

L'authentification est la première ligne de défense. Un seul point faible suffit à compromettre tout le système.


// ═══════════════════════════════════════════════════════════
// 1️⃣ HACHAGE SÉCURISÉ DES MOTS DE PASSE
// ═══════════════════════════════════════════════════════════

// ✅ À l'inscription :
$password_hashed = password_hash($_POST['password'], PASSWORD_ARGON2ID);
// Stocker $password_hashed dans la BDD (JAMAIS le mot de passe en clair !)

// ✅ À la connexion :
if (password_verify($_POST['password'], $user['password_hashed'])) {
    // Mot de passe correct
    $_SESSION['user_id'] = $user['id'];
}

// ═══════════════════════════════════════════════════════════
// 2️⃣ CONFIGURATION SESSIONS SÉCURISÉES
// ═══════════════════════════════════════════════════════════

// ✅ Configuration avant session_start()
ini_set('session.cookie_httponly', 1);  // Protège contre XSS
ini_set('session.cookie_secure', 1);    // HTTPS uniquement
ini_set('session.use_strict_mode', 1);  // Refuse sessions non initialisées

session_start();

// ✅ Régénérer l'ID après connexion (protection fixation de session)
session_regenerate_id(true);

// ═══════════════════════════════════════════════════════════
// 3️⃣ CONTRÔLE DES DROITS D'ACCÈS
// ═══════════════════════════════════════════════════════════

function requireAuth() {
    if (!isset($_SESSION['user_id'])) {
        header('Location: login.php');
        exit;
    }
}

function requireRole($role) {
    requireAuth();
    if ($_SESSION['user_role'] !== $role) {
        die('Accès refusé');
    }
}

// 💡 Utilisation :
requireRole('admin');  // Sur page admin

// ═══════════════════════════════════════════════════════════
// 4️⃣ PROTECTION FORCE BRUTE
// ═══════════════════════════════════════════════════════════

// ✅ Limiter les tentatives de connexion
$_SESSION['login_attempts'] = ($_SESSION['login_attempts'] ?? 0) + 1;

if ($_SESSION['login_attempts'] > 5) {
    $wait_time = pow(2, $_SESSION['login_attempts'] - 5) * 60;
    die("Trop de tentatives. Réessayez dans " . $wait_time . " secondes.");
}

Fondamentaux authentification :

  • ✅ password_hash() et password_verify() uniquement
  • ✅ Sessions sécurisées (httponly, secure, regenerate_id)
  • ✅ Contrôle des droits sur CHAQUE page protégée
  • ✅ Protection contre force brute (limitation tentatives)
